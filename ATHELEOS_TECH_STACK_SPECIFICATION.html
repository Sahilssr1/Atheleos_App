1 Frontend Architecture & Client Stack

2 Backend & Serverless Compute

ATHELEOS uses a hybrid serverless model: Firebase Cloud Functions handle CPU-heavy operations (video transcoding, integrity triggers, cleanup crons) while Cloudflare Workers act as a global edge upload gateway with zero egress fees.

Firebase Cloud Functions (Node.js 20)
Written in TypeScript (functions/src/index.ts). High-memory containers (2GB RAM) executing automated triggers, media jobs, and administration endpoints.
Cloudflare Edge Worker
Deployed at atheleos-media-worker on Cloudflare's global CDN edge. Handles token validation, streaming uploads, deduplication, and rate limiting.

3 Database & Storage Layer

The persistence tier couples Google Cloud Firestore for real-time document synchronization and querying with Cloudflare R2 for S3-compatible, zero-egress object storage.

Google Cloud Firestore
Document-based NoSQL database with client-side offline persistence (100MB LRU cache). Governed by granular security rules (firestore.rules) and composite indexes (firestore.indexes.json).
Cloudflare R2 Storage Bucket
Bucket: atheleos-media. Stores raw ingested video masters, transcode renditions, high-res photos, WebP thumbnails, and story assets with CDN caching.

4 Authentication, Email & Security

Security in ATHELEOS combines OAuth standards, short-lived one-time passwords, cryptographic token checks, and server-side authorization boundaries.

Firebase Authentication & OAuth
Identity management supporting Email & Password authentication and Google Sign-In (google_sign_in). Issues signed RS256 JWT tokens with custom user claims.
Hostinger SMTP Email Gateway
Dedicated TLS email relay (smtp.hostinger.com:465) configured with DKIM/SPF from contact@atheleos.in for OTPs and notifications.
Edge JWT Verification
Cloudflare Worker cryptographically validates Firebase ID tokens directly against Google's public x509 certificates before admitting requests.
Zero-Trust Firestore Security
firestore.rules strictly prevents client edits to verified badges, reference counters, report states, or impersonating other athletes.
Workflow / Component Implementation Detail Security Guarantees
Email OTP Verification 6-digit cryptographically generated OTP stored in email_otps/{email} with timestamp. Dispatched via Nodemailer. 10-minute expiry window, single-use invalidation upon verification, rate-limited resend cooldowns.
Server Password Reset HTTPS endpoint resetPasswordWithOtp requires valid OTP matching the user before calling admin.auth().updateUser(). Enforces strict password complexity (min 8 chars, uppercase, lowercase, numbers, special characters) entirely on server.
Admin & Moderation Separation Role-based custom claims (admin, moderator) checked by Firestore rules and Cloud Functions. Clients cannot approve athlete verification applications, delete foreign media, or modify sports taxonomy.

match /users/{userId} {
  allow read: if true;
  allow update: if request.auth.uid == userId
    && !request.resource.data.diff(resource.data).affectedKeys()
        .hasAny(['verified', 'verificationBadge', 'verificationLevel']);
}
